Sıfırdan GPT Yapımı

📚 L5 · LLM Serisi⏱ ~45 dakika🖥 İnteraktif Simülasyon
Bu derste öğrenecekleriniz: Şimdiye kadar öğrendiğiniz her şeyi birleştirerek çalışan bir GPT eğiteceksiniz: tokenization, embedding, transformer blokları, eğitim döngüsü ve metin üretimi. Bu ders platformun kalbidir.

Her Şeyi Birleştiriyoruz

Önceki 4 derste öğrendiklerinizi tek bir modele dökelim. Elinizde: tokenization (L1), embedding (L2), self-attention (L3), transformer bloğu (L4) var. Eksik olan tek şey: bunları birleştirip "bir sonraki karakteri tahmin et" göreviyle eğitmek.

💡 TEMEL FİKİR

GPT'ye "bir sonraki karakteri tahmin etme oyunu" öğretiyoruz. Milyonlarca metin gösterilir: "Ankara Türkiye'nin başkent___" → doğru cevap "idir". Kaybı azaltmak için model dilbilgisi, dünya bilgisi, hatta basit mantık öğrenmek zorundadır. İşte "zeka" buradan doğar: tahmin oyununda ustalaşmak anlamayı gerektirir.

Bu Ders Neden Zor?

"Sıfırdan GPT" adı kulağa basit geliyor ama aslında 5 farklı disiplini birleştiriyor: tokenizasyon + embedding + attention + transformer + eğitim optimizasyonu. Her biri ayrı bir ders. Burada yapacağımız şey, bu parçaları tek tek değil, birbirine bağlayarak görmek. Tıpkı LEGO gibi: her parça basit, ama birleşince ortaya çıkan yapı karmaşık.

⚠️ DİKKAT Eğer önceki derslerden (tokenizasyon, embedding, self-attention, transformer) herhangi birini tam anlamadıysanız, burada takılmanız çok normal. Bu dersi bitirdikten sonra geriye dönüp eksik parçaları tamamlayın. Kimse ilk seferde anlamaz — ben de anlamadım.

Adım 0: Oyunu Anlayalım (Kod Yok, Sadece Kafa Yor)

Kod yazmadan önce, ne yaptığımızı %100 anlamamız gerek. İşte basit bir metin: 

"merhaba dünya"

Karakter seviyesinde tokenizasyon yapalım: 

# "merhaba dünya" metnindeki benzersiz karakterler:
# {' ', 'a', 'b', 'd', 'e', 'h', 'l', 'm', 'n', 'r', 'u', 'y', 'z'}
# vocab_size = 13

# Her karaktere bir numara verelim (stoi = string to index):
# ' '→0, 'a'→1, 'b'→2, 'd'→3, 'e'→4, 'h'→5, 'l'→6, 'm'→7, 'n'→8, 'r'→9, 'u'→10, 'y'→11, 'z'→12

# "merhaba" → [7, 4, 9, 5, 1, 2, 1]
# "dünya"   → [3, 12, 8, 11, 1]
🧠 DÜŞÜN

Model "merhaba" kelimesini gördüğünde, her pozisyonda bir sonraki harfi tahmin etmeli:
• "m" gördü → "e" tahmin et
• "me" gördü → "r" tahmin et
• "mer" gördü → "h" tahmin et
...ve böyle devam eder.

Peki ya model "merhaba" kelimesini hiç görmemişse? O zaman rastgele tahmin yapar. Eğitim, modelin "bu bağlamda genellikle bu harf gelir" öğrenmesini sağlar.

Adım 1: Veri Hazırlama — Batch ve Hedef

import torch
import torch.nn as nn
import torch.nn.functional as F

# Eğitim metni (Colab'da Shakespeare veya Türkçe bir külliyat kullanın)
with open("veri.txt", encoding="utf-8") as f:
    metin = f.read()

# Karakter seviyesinde tokenizer (en basit yaklaşım)
karakterler = sorted(set(metin))
vocab_size = len(karakterler)
stoi = {ch: i for i, ch in enumerate(karakterler)}  # string → int
itos = {i: ch for ch, i in stoi.items()}           # int → string

encode = lambda s: [stoi[c] for c in s]
decode = lambda l: "".join(itos[i] for i in l)

veri = torch.tensor(encode(metin), dtype=torch.long)
n = int(0.9 * len(veri))
train_veri, val_veri = veri[:n], veri[n:]

block_size = 64   # Bağlam penceresi: 64 karaktere bakarak sonraki tahmin

def batch_al(split):
    v = train_veri if split == "train" else val_veri
    ix = torch.randint(len(v) - block_size, (32,))   # 32 rastgele konum
    x = torch.stack([v[i:i+block_size] for i in ix])
    y = torch.stack([v[i+1:i+block_size+1] for i in ix])  # Hedef: 1 kaydırılmış!
    return x, y

# KRİTİK NOKTA: y = x'in 1 karakter sağa kaymış hali.
# Model her pozisyonda "bir sonrakini" tahmin etmeyi öğrenir.
🔍 NEDEN BÖYLE?

Batch boyutu = 32: Aynı anda 32 farklı metin parçası üzerinde çalışırız. Neden? Çünkü GPU'lar paralel çalışır — tek örnek yerine 32 örnek beslerseniz 32 kat hızlı eğitim.

block_size = 64: Model sadece son 64 karaktere bakar. Neden 64? Deneyimsel olarak: kısa bağlamlar (32) kelime sınırlarını keser, uzun bağlamlar (256+) GPU belleğini şişirir. 64, Shakespeare ve Türkçe metinler için iyi bir denge.

# Metin: "merhaba dünya" → encode: [7,4,9,5,1,2,1,0,3,12,8,11,1]

# Batch 1, konum 2'den başla (i=2):

# y = veri[3:7] = [5,1,2,1]  → "hab"

# Batch 2, konum 0'dan başla (i=0):
# x = veri[0:4] = [7,4,9,5]  → "merh"

# x: (2, 4) — 2 batch, 4 konum
# y: (2, 4) — aynı boyut, ama 1 kaymış

Çünkü model her pozisyonda bir tahmin yapar. x[0][0] = "r" girdisi → model "h" tahmin etmeli (y[0][0]). x[0][1] = "rh" girdisi → model "a" tahmin etmeli (y[0][1]). Her pozisyon ayrı bir eğitim örneği!

Adım 2: Model — Mini GPT

class Head(nn.Module):
    """Tek bir attention başlığı (L3'te öğrendiklerimiz)."""
    def __init__(self, embed_dim, head_size):
        super().__init__()
        self.k = nn.Linear(embed_dim, head_size, bias=False)
        self.q = nn.Linear(embed_dim, head_size, bias=False)
        self.v = nn.Linear(embed_dim, head_size, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k, q, v = self.k(x), self.q(x), self.v(x)
        wei = q @ k.transpose(-2, -1) * C**-0.5
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))  # Geleceğe bakma!
        wei = F.softmax(wei, dim=-1)
        return wei @ v

class MiniGPT(nn.Module):
    def __init__(self):
        super().__init__()
        n_embd, n_head, n_layer = 64, 4, 3
        self.token_emb = nn.Embedding(vocab_size, n_embd)
        self.pos_emb = nn.Embedding(block_size, n_embd)
        self.ln_f = nn.LayerNorm(n_embd)
        self.kafa = nn.Linear(n_embd, vocab_size)

        # Basitlik için tek başlık × 3 katman yazıyoruz (Colab CPU'da bile çalışır)
        self.bloklar = nn.ModuleList()
        for _ in range(n_layer):
            self.bloklar.append(nn.ModuleDict({
                "ln1": nn.LayerNorm(n_embd),
                "att": Head(n_embd, n_embd // n_head),
                "ln2": nn.LayerNorm(n_embd),
                "ffn": nn.Sequential(
                    nn.Linear(n_embd, 4 * n_embd), nn.GELU(), nn.Linear(4 * n_embd, n_embd)
                )
            }))

    def forward(self, idx, hedefler=None):
        B, T = idx.shape
        x = self.token_emb(idx) + self.pos_emb(torch.arange(T))
        for b in self.bloklar:
            x = x + b["att"](b["ln1"](x))
            x = x + b["ffn"](b["ln2"](x))
        x = self.ln_f(x)
        logits = self.kafa(x)   # (B, T, vocab_size)

        kayip = None
        if hedefler is not None:
            B, T, C = logits.shape
            kayip = F.cross_entropy(logits.view(B*T, C), hedefler.view(B*T))
        return logits, kayip

    @torch.no_grad()
    def uret(self, idx, max_yeni=200):
        for _ in range(max_yeni):
            idx_kes = idx[:, -block_size:]       # Bağlam penceresini aşma
            logits, _ = self(idx_kes)
            olasiliklar = F.softmax(logits[:, -1, :], dim=-1)  # Son pozisyon
            sonraki = torch.multinomial(olasiliklar, 1)        # Olasılığa göre örnekle
            idx = torch.cat([idx, sonraki], dim=1)
        return idx

model = MiniGPT()
print(f"Parametre sayısı: {sum(p.numel() for p in model.parameters()):,}")
🧱 LEGO BLOKLARI

MiniGPT'yi 5 katmanda düşünün:

1. Embedding katmanı: Her karakteri 64 boyutlu vektöre çevirir. "a" harfi artık sadece bir harf değil, 64 sayıdan oluşan bir "parmak izi".

2. Pozisyon Encoding: "merhaba"da 1. harf mi 5. harf mi? Model bilmiyor. pos_emb her pozisyona (0,1,2...63) ayrı bir vektör ekler.

3. Transformer Blokları (×3): Attention + feed-forward. Her blok, kelimeler arasındaki ilişkileri öğrenir. 1. blok dilbilgisi, 2. blok anlam, 3. blok bağlam.

4. LayerNorm: Değerlerin uçmasını engeller. Sinir ağlarında stabilite şart.

5. Çıkış Katmanı (kafa): 64 boyutlu vektörü vocab_size boyutuna çevirir. Her boyut = bir karakter için skor.

# token_emb: 65 × 64 = 4,160

#   - ln1: 64 × 2 = 128 (weight + bias)

Adım 3: Eğitim Döngüsü

optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

for adim in range(3000):
    x, y = batch_al("train")
    logits, kayip = model(x, y)
    optimizer.zero_grad()
    kayip.backward()
    optimizer.step()
    if adim % 500 == 0:
        print(f"Adım {adim}: kayıp = {kayip.item():.4f}")

# Kayıp ~2.5'tan ~1.2'ye düştüğünde model dilbilgisini çözmeye başlamış demektir
# (rastgele tahmin: ln(vocab_size) ≈ ln(65) ≈ 4.17)
📊 LOSS NE DEMEK?

Kayıp (loss) = modelin tahmininin ne kadar yanlış olduğunun ölçüsü.

Kayıp = 4.17 → Rastgele tahmin (henüz eğitim yok)
Kayıp = 2.0 → Kelime başına 2.0 "şanslı tahmin" (orta düzey)
Kayıp = 1.0 → Oldukça iyi, akıcı metin üretir
Kayıp = 0.5 → Mükemmel ama overfit (ezberlemiş) olabilir

Cross entropy basitçe: "Modelin %90 emin olması gereken yerde %10 emin olması ne kadar ceza almalı?" sorusunun cevabı.

🎲 RASTGELE vs. ÜRETİM

Eğitimsiz model: Her karakter eşit olasılıkta (%1.5). Sonuç: "a b q z x j k" gibi rastgele harfler.

Eğitimli model: "m"den sonra "e" %80 olasılıkla gelir, "x"den sonra "y" %1. Sonuç: Akıcı, okunabilir metin.

Bu tek değişiklik bile (eşit olasılık → öğrenilmiş olasılık) "anlamlı metin" üretmek için yeterli!

# Başlangıç: idx = [0] (boş token, vocab'da 0 numaralı karakter)

# Adım 1: Model [0] gördü
#   → logits: [0.1, 0.05, 0.8, ...]  → softmax → [0.02, 0.01, 0.25, ...]
#   → multinomial örnekleme: "e" seçildi (toplam 1.0'e normalize edilmiş dağılımdan)
#   → idx = [0, 4]  ("e" = 4 numaralı karakter)

# Adım 2: Model [0, 4] gördü
#   → Son pozisyonun logits'i alınır (sadece son karakterin tahmini yeterli)
#   → "r" seçildi → idx = [0, 4, 9]  ("er")

# Adım 3: Model [0, 4, 9] gördü
#   → "h" seçildi → idx = [0, 4, 9, 5]  ("erh")

# ... 300 adım sonra: "erhaba dünya. Bugün hava çok güzel..."
❓ SORU Neden her adımda sadece son pozisyona bakıyoruz?

Çünkü causal (tek yönlü) attention kullanıyoruz. Model geçmişe bakar, geleceğe bakamaz. Son pozisyon = tüm geçmişin özeti. Önceki pozisyonların tahminleri zaten yapılmış, o tokenlar artık sabit. Sadece "bir sonraki" karakteri tahmin etmemiz gerekiyor.

Sampling: temperature ve top-k

def uret_v2(model, idx, max_yeni=200, temperature=1.0, top_k=None):
    for _ in range(max_yeni):
        logits, _ = model(idx[:, -block_size:])
        logits = logits[:, -1, :] / temperature  # Düşük T = güvenli, yüksek T = yaratıcı
        if top_k:
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = float("-inf")  # Sadece en iyi k aday
        probs = F.softmax(logits, dim=-1)
        sonraki = torch.multinomial(probs, 1)
        idx = torch.cat([idx, sonraki], dim=1)
    return idx

# temperature=0.1 → neredeyse hep en olası token (tekdüze ama tutarlı)
# temperature=1.5 → riskli seçimler (yaratıcı ama saçmalayabilir)
# top_k=50 → sadece en iyi 50 adaydan seç (saçmalama azalır)
🎰 SLOT MAKİNESİ ANALOGİSİ

Softmax çıktısını bir rulet çarkı gibi düşünün:

temperature=0.1 → Çark neredeyse hep aynı deliğe girer (en yüksek olasılık). Sıkıcı ama güvenli.
temperature=1.0 → Çark gerçekçi dağılımda döner. Dengeli.
temperature=2.0 → Çark neredeyse tamamen rastgele döner. Yaratıcı ama kaotik.

top_k=50 → Çarkın sadece en geniş 50 bölmesi kalır, dar bölmeler kapanır. Saçma kelimeler tamamen elenir.

Örnek: Farklı Temperature'larda Çıktı

# Prompt: "Bugün hava çok"

# temperature=0.1 (greedy'e yakın):
# "Bugün hava çok güzel. Bugün hava çok güzel. Bugün hava çok güzel."
# → Tekrarlanıyor! En olası token hep aynı.

# temperature=0.7 (dengeli):
# "Bugün hava çok güzel, dışarı çıkıp yürüyüş yapmak istiyorum."
# → Akıcı ve çeşitli.

# temperature=1.5 (yaratıcı):
# "Bugün hava çok zorlu ve aniden karanlık bastırdı, sanki gök deliniyormuş gibi."
# → Yaratıcı ama bazen saçmalıyor ("gök deliniyormuş" anlamsız).

# temperature=2.5 (kaotik):
# "Bugün hava çok qwerty pijama dans ediyor telefon uçak."
# → Tamamen rastgele çöp.

Modern Eklemeler: Neler Eksik?

Yukarıdaki model çalışıyor ama 2026 standartlarına göre eksik. İşte ekleyebileceğiniz iyileştirmeler (zorluk sırasına göre): 

# 1. KOLAY: Dropout (overfit önleme)
self.dropout = nn.Dropout(0.1)  # %10 nöron rastgele kapat
x = self.dropout(x)

# 2. ORTA: Multi-head attention (tek başlık yerine 4 başlık)
class MultiHead(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.heads = nn.ModuleList([Head(embed_dim, embed_dim // num_heads) for _ in range(num_heads)])
        self.proj = nn.Linear(embed_dim, embed_dim)
    def forward(self, x):
        return self.proj(torch.cat([h(x) for h in self.heads], dim=-1))

# 3. ORTA: Weight tying (girdi ve çıkış embedding'ini paylaş)
# Parametre sayısını azaltır, performansı artırabilir
self.kafa.weight = self.token_emb.weight

# 4. ZOR: KV-cache (üretim hızlandırma)
# Her adımda tüm geçmişi yeniden hesaplamak yerine, sadece yeni token için
# attention hesapla. 10-20x hız kazancı!

# 5. ZOR: RoPE (Rotary Position Embedding)
# pozisyon encoding'i embedding'e çarpmak yerine, attention skorlarına
# sinusoidal dönüşüm uygular. Daha uzun bağlamlar için daha iyi.
❓ SORU KV-cache nedir ve neden bu kadar hızlandırır?

Normalde her üretim adımında, tüm bağlam (örn. 64 token) için attention hesaplanır: 64×64 attention matrisi. Ama bağlamın sadece son token'ı değişti! KV-cache, önceki tokenlar için hesaplanmış key ve value'ları saklar. Her adımda sadece yeni token için K ve V hesaplanır, eskilerle birleştirilir.

Matematik: O(T²) → O(T). 64 token için 64 kat hız kazancı!

Sık Yapılan Hatalar ve Çözümleri

🐛 HATA 1 "Loss 4.17'de kaldı, düşmüyor"

Olası nedenler:
• Öğrenme oranı çok yüksek (3e-3) → 3e-4'e düşürün
• Model çok küçük (n_embd=8) → 64'e çıkarın
• Veri setinde Türkçe karakterler bozuk → encoding="utf-8" ekleyin
• Gradient patlaması → torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
🐛 HATA 2 "Model 'e' harfini çok sık söylüyor, başka harf yok"

Model "güvenli" olan en yüksek frekanslı harfi seçiyor. Çözüm:
• Daha uzun eğitim (3000 → 10000 adım)
• Daha büyük model (n_layer=3 → 6)
• Daha fazla veri (tek kitap → 10 kitap)
🐛 HATA 3 "CUDA out of memory"

GPU belleği yetmiyor. Çözüm:
• batch_size 32 → 16 veya 8
• block_size 64 → 32
• n_layer 3 → 1 (sadece test için)
• torch.backends.cudnn.benchmark = False
