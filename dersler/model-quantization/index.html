Model Quantization Derinlemesine

Bu derste öğrenecekleriniz: Kayan nokta aritmetiği (FP32/FP16/BF16), simetrik/asimetrik quantization, kalibrasyon, PTQ vs QAT ve GGUF format ailesi (Q4_K_M vs Q8_0). Quantization'ın "neden" ve "nasıl"ını derinlemesine kavrayın.

Kayan Nokta Aritmetiğinin Anatomisi

import numpy as np
import torch

# 32-bit float (FP32): 1 sign + 8 exponent + 23 mantissa
x = np.float32(3.14159)
print(x.view(np.uint32))  # 0x40490FD0 →
# Bitler: 01000000010010010000111111010000
# İşaret: 0 (+), Üs: 10000000 (2^1), Ondalık: ~0.5708
# Değer: (-1)^0 × 2^(128-127) × 1.5708 ≈ 3.14159

# FP16: 1+5+10 → üs aralığı dar [2^-14, 2^15], mantissa 10 bit
# BF16: 1+8+7  → FP32'nin üs aralığı, mantissa 7 bit
# FP16: dar aralıkta daha hassas (ince çözünürlük)
# BF16: çok daha geniş aralık ama daha kaba; küçük değerlerde underflow'a düşmez
print(torch.tensor(1e5, dtype=torch.float16))  # inf (taşma!)
print(torch.tensor(1e5, dtype=torch.bfloat16)) # 100352.0 (idare eder)
print(torch.tensor(1e-8, dtype=torch.float16)) # 0.0 (alttan taşma!)
print(torch.tensor(1e-8, dtype=torch.bfloat16))# 1e-08 (korunur)
💡 ANALOJİ

FP32 = milimetre bölmeli cetvel, FP16 = santimetre bölmeli cetvel, INT8 = sadece 256 tam sayı çizgisi (-128..127 işaretli; 0..255 işaretsiz). Quantization, ince cetveldeki okumayı en yakın kaba çizgiye oturtmaktır — adımlar büyüdükçe ayrıntı kaybolur. Her model katmanının kabul edebileceği kayıp farklıdır.

Simetrik vs Asimetrik Quantization

# Simetrik: sıfır noktası 0'a sabitlenir (ağırlıklar genelde sıfır merkezli)
def simetrik_quant(x, bit=8):
    qmax = 2 ** (bit - 1) - 1            # 8-bit → 127, 4-bit → 7
    maks = torch.abs(x).max().clamp(min=1e-8)  # sıfıra bölmeyi önle
    olcek = maks / qmax
    q = torch.clamp(torch.round(x / olcek), -qmax, qmax)
    return q.to(torch.int8), olcek       # bit≤8 için int8 yeterli

# Asimetrik: min-max arasına eşler (aktivasyonlar tek yönlü olabilir: ReLU ≥ 0)
def asimetrik_quant(x, bit=8):
    qmax = 2 ** bit - 1                  # 8-bit → 255, 4-bit → 15
    mn, mx = x.min(), x.max()
    olcek = ((mx - mn) / qmax).clamp(min=1e-8)
    sifir_noktasi = torch.clamp(torch.round(-mn / olcek), 0, qmax)
    q = torch.clamp(torch.round(x / olcek + sifir_noktasi), 0, qmax)
    return q.to(torch.uint8), olcek, sifir_noktasi

# W8A8 = ağırlıklar 8-bit + aktivasyonlar 8-bit
# (simetrik/asimetrik şema seçimi W8A8 tanımından bağımsız, ayrı bir karardır)

Kalibrasyon: Hangi Ölçek?

Quantization'da en kritik karar her tensörün ölçeğini (scale) nasıl seçtiğinizdir:

  • Min-Max: Gözlenen en uç değerlerle ölçek — aykırı değerler (outlier) aralığı şişirir, çözünürlük düşer.
  • Percentile (99.9): Aykırıları kırp — çoğu değer için daha iyi çözünürlük.
  • KL Divergence (TensorRT): Orijinal ve quantize dağılım arasındaki farkı minimize et.
  • Per-channel: Her çıkış kanalına ayrı ölçek — ağırlıklarda standart (per-tensor'dan genelde daha iyi, fark modele ve bit genişliğine bağlıdır). Aktivasyonlar akışkandır; her girdide ölçek yeniden hesaplanacağı için per-channel aktivasyon pratikte nadirdir, genelde per-tensor (dinamik) kullanılır.

Not: Bu kalibrasyon yöntemleri aktivasyon ölçeklerini belirlemek içindir; ağırlık ölçekleri doğrudan ağırlık istatistiklerinden hesaplanabilir, veri gerekmez.

PTQ vs QAT

# PTQ (Post-Training Quantization) — eğitilmiş modeli doğrudan dönüştür:
# Artıları: dakikalar içinde, eğitim verisi az (512 örnek kalibrasyon)
# Eksileri: INT4'te ciddi kalite kaybı olabilir

# QAT (Quantization-Aware Training) — sahte quantization'ı eğitime dahil et:
def sahte_quant(x, olcek, qmax=127):
    q = torch.clamp(torch.round(x / olcek), -qmax, qmax)
    x_q = q * olcek
    return x + (x_q - x).detach()   # Straight-Through Estimator (STE)
    # forward: quantize edilmiş değer
    # backward: gradyan sabitlik bölgesinde "atlar" (türev=1 varsayılır),
    # clamp edilen (doygun) bölgede ise sıfırlanmalıdır (pass-through maskesi)
# Not: Bu formülle olcek'e giden gradyan detach ile KESİLİR — ölçek öğrenmez.
# Ölçeğin öğrenilmesi için LSQ (Learned Step Size) gibi özel türev gerekir.

GPTQ ve AWQ: LLM'lere Özel PTQ Yöntemleri

  • GPTQ: Katman katman, Hessian (2. türev) bilgisini kullanarak quantization hatasını telafi edecek şekilde diğer ağırlıkları ayarlar.
  • AWQ: "Ağırlıkların sadece ~%1'i kalite için kritiktir" bulgusu — bu kritik (salient) kanallar ağırlık büyüklüğüne değil aktivasyon istatistiklerine göre belirlenir. AWQ onları FP16'da tutmak yerine (karma hassasiyet donanımda verimsizdir), önemli kanalları ölçekleyerek quantization hatasını azaltır — bütün matris hâlâ homojen 4-bit kalır.
  • Kalite: Q4_K_M karışık hassasiyet kullandığı için perplexity olarak GPTQ/AWQ 4-bit ile benzer düzeydedir; "belirgin üstünlük" iddiası genellenemez. Asıl fark dağıtım ortamıdır: GPTQ/AWQ GPU çekirdekleriyle (vLLM vb.) yüksek hız verir, GGUF ise CPU / Apple Silicon / karma çıkarımda güçlüdür.
