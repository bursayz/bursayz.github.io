Tokenization: Metni Sayılara Çevirmek

📚 L1 · LLM Serisi⏱ ~25 dakika🖥 İnteraktif Araç
Bu derste öğrenecekleriniz: Modelin metni nasıl gördüğü, BPE algoritması, özel token'lar ve bağlam penceresi. LLM'in "düşünme" sürecinin ilk adımı burada başlar.

Model Metni Nasıl Görür?

Bilgisayarlar sadece sayıları anlar. "Merhaba dünya" yazısı bilgisayar için anlamsızdır — önce sayılara çevrilmesi gerekir. Bu işleme tokenization denir. (Aşağıdaki token ID'leri örnek değerlerdir.)

Neden Kelime Kelime Değil?

En basit yaklaşım kelime bazlı olurdu ama sorunlu: "koşmak", "koştu", "koşacak" hep farklı kelime sayılır. Kelime haznesi çok büyür ve İngilizce dışındaki dillerde patlar. Alt-kelime (subword) tokenizasyonu dengeyi bulur: sık kullanılan kelimeler tek token, nadir kelimeler parçalara bölünür. 

# tiktoken ile (OpenAI'ın tokenizer'ı)
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")

metin = "yapay zeka öğreniyorum"
tokenlar = enc.encode(metin)
print(tokenlar)  # [88, 391, 352, 1167, 53413, 17372, 11257, 1466, 16618, 34106]

# Token ID'si → orijinal parça
# DİKKAT: Byte-level BPE'de bir karakter birden çok token'a bölünebilir.
# Örneğin "ö" gibi bazı karakterler tek başına decode edilemez — "" (replacement char) üretebilir.
# Güvenli kullanım: decode_single_token_bytes ile byte seviyesinde inceleyin.
for t in tokenlar:
    print(t, "→", enc.decode_single_token_bytes(t))
# 88 → b'y'
# 391 → b'ap'
# 352 → b'ay'
# 1167 → b' z'
# 53413 → b'eka'
# 17372 → b' \xc3\xb6'  (ö'nün byte'ları)
# 11257 → b'\xc4\x9f'  (ğ'nün byte'ları)
# 1466 → b'ren'
# 16618 → b'iy'
# 34106 → b'orum'

BPE Algoritması: Adım Adım

BPE (Byte Pair Encoding), en sık geçen karakter çiftlerini tekrar tekrar birleştirerek kelime haznesi oluşturur. Aşağıdaki örnek kavramsal BPE'dir; modern tokenizer'larda (cl100k_base, Llama-3) byte-level BPE kullanılır ve başlangıç sözlüğü 256 byte'tır. Gerçek BPE önce kelimelere ayırır (pre-tokenization), kelime frekansları üzerinden çalışır ve birleştirme kurallarını (merge list) saklar.

  1. Başta her karakter ayrı bir token (gerçekte 256 byte): ["k","a","n","a","t"]
  2. Veri setinde en çok birlikte geçen çift bulunur: ("k","a") → yeni token "ka"
  3. Tüm metinlerde bu çift birleştirilir: ["ka","n","a","t"]
  4. Bu adım tekrarlanır; kelime haznesi boyutu (vocab size) kadar kural oluşur → kelime haznesi oluşur
  5. Kural listesi (merge list) inference sırasında da sırayla uygulanır — yani bir tokenizasyon aynı kuralları tekrar tekrar kullanır.
# Basit BPE simülasyonu (kavramsal; gerçek BPE kelime frekansları üzerinden çalışır)
# Not: Eşitlik durumunda ilk görülen çift seçilir (max() davranışı)
def bpe_egit(metin, birlesme_sayisi):
    tokenlar = list(metin)
    for tur in range(birlesme_sayisi):
        # En sık geçen çifti bul
        siklik = {}
        for i in range(len(tokenlar) - 1):
            cift = (tokenlar[i], tokenlar[i+1])
            siklik[cift] = siklik.get(cift, 0) + 1
        if not siklik: break
        en_sik = max(siklik, key=siklik.get)  # Eşitlikte ilk eklenen çift
        yeni_token = "".join(en_sik)
        # Birleştir (tek kural)
        yeni_tokenlar = []
        i = 0
        while i < len(tokenlar):
            if i < len(tokenlar)-1 and (tokenlar[i], tokenlar[i+1]) == en_sik:
                yeni_tokenlar.append(yeni_token)
                i += 2
            else:
                yeni_tokenlar.append(tokenlar[i])
                i += 1
        tokenlar = yeni_tokenlar
        print(f"Tur {tur+1}: Birleşen: {en_sik} → '{yeni_token}'  →  {tokenlar}")
    return tokenlar

bpe_egit("kanat kanat kanat", 3)
# Tur 1: Birleşen: ('k','a') → 'ka'  →  ['ka','n','a','t',' ','ka','n','a','t',' ','ka','n','a','t']
# Tur 2: Birleşen: ('ka','n') → 'kan'  →  ['kan','a','t',' ','kan','a','t',' ','kan','a','t']
# Tur 3: Birleşen: ('kan','a') → 'kana'  →  ['kana','t',' ','kana','t',' ','kana','t']
# Dikkat: Tüm çiftler eşit sıklıkta (3 kez). Eşitlik durumunda ilk eklenen çift ('k','a') seçilir.
# Bu örnekte "en sık çift" kavramı anlam kazanmıyor — "kanat kanat kanat kalem" gibi eşit olmayan bir örnek daha öğretici olurdu.

# Gerçek BPE'de birleştirme kuralları (merge list) döndürülür ve yeni metin encode edilirken
# sırayla uygulanır. Bu basit simülasyon yalnızca tokenlanmış metni döndürür.

İnteraktif BPE Aracı

Aşağıya herhangi bir Türkçe/İngilizce metin yazın. Örnek bir simülasyon aracı kelimeleri nasıl parçaladığını görebilirsiniz. Bu araç gerçek bir tokenizer değildir; gerçek davranış için tiktoken veya Hugging Face Tokenizers kullanın.

Canlı Tokenization Aracı

Özel Token'lar

# LLM'lerde metnin içine yapısal işaretleyiciler (özel token'lar) eklenir:
# <|begin_of_text|>, <|endoftext|>, <|eot_id|> gibi formatlar yaygındır.
# [BOS]/[EOS] gösterimi bazı kaynaklarda kullanılır ama genel standart değildir.
# [CLS]/[SEP] ise BERT model ailesine özgüdür.
# Önemli: Model bu token'lara eğitim sırasında anlam kazandırır; "gizli komut" değillerdir.

# Örnek chat template (Llama-3 tarzı):
metin = """<|begin_of_text|>
<|start_header_id|>system<|end_header_id|>

Sen yardımcı bir asistansın.<|eot_id|>
<|start_header_id|>user<|end_header_id|>

Merhaba!<|eot_id|>
<|start_header_id|>assistant<|end_header_id|>

Merhaba! Size nasıl yardımcı olabilirim?<|eot_id|>"""

# Tokenizer bu metni sayı dizisine çevirir.
# Not: tiktoken varsayılan olarak özel token'ları encode etmez;
# allowed_special={"<|...|>"} veya encode_with_special kullanmanız gerekir.
# Gerçek Llama-3 tokenizer'ında "system" ID'si 9125'tir (78191 "assistant" kelimesinin ID'sidir).

Bağlam Penceresi (Context Window)

  • Model aynı anda sadece belirli sayıda token "görebilir". Bu limit: bağlam penceresi (girdi + çıktı token'larının toplamı).
  • GPT-3.5: ilk sürüm 4K, sonra 16K token. GPT-4: orijinal 8K/32K; Turbo ve GPT-4o: 128K token. Claude 3.5: 200K token. Güncel değerler için model dokümantasyonuna bakın (Eylül 2026 itibarıyla 1M+ bağlam sunan modeller mevcut).
  • 1 token ≈ 0.75 İngilizce kelime (cl100k_base için). Türkçe kelime oranı tokenizer'a göre değişir; cl100k_base'de yaklaşık 0.5-0.6 civarıdır, yeni tokenizer'larda daha yüksek olabilir. "Yaklaşık" olarak değerlendirilmeli.
  • Pencere dolunca: API'lerde çoğunlukla hata döner veya giriş kesilir; "unutma/özetleme" davranışını uygulama katmanı belirler, model kendisi otomatik olarak eski token'ları silmez.
⚠️ Türkçe ve Tokenization

Türkçe eklemeli bir dildir — "evlerimizden" = 4 anlamlı morfem (ev + ler + imiz + den). BPE token'ları morfemlerle bire bir örtüşmez; ikisi farklı kavramlardır. İngilizce için eğitilen tokenizer Türkçe'yi çok parçalar → daha fazla token, daha yüksek maliyet, daha yavaş çalışma. Türkçe LLM geliştirirken Türkçe tokenizer eğitmek büyük avantaj sağlar.
