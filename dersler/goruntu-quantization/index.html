Görüntü Modellerinde Quantization

📚 G9 · Görüntü Serisi⏱ ~25 dakika
Bu derste öğrenecekleriniz: Quantization'ın görüntü modellerine özgü zorlukları, VAE quantization'ının renk etkisi, TensorRT/ONNX ile hızlandırma ve pratik karar kılavuzu. LLM ve görüntü quantization farkları.

LLM vs Görüntü Modeli Quantization Farkı

LLM Quantization
Hata = metin kalitesi
İnsan okuyup fark edebilir
Geniş tolerans
vs
Görüntü Quantization
Hata = renk kayması / doku bozukluğu
Piksel düzeyinde görünür
Daha hassas

LLM'de INT4 neredeyse görünmezdir; görüntüde VAE decoder'ı quantize ederseniz renkler kayabilir, bulanıklık artabilir. Fakat UNet quantization daha güvenlidir.

Hangi Katmanı Ne Kadar Sıkıştırmalı?

# Görüntü modellerinde quantization riski sıralaması (düşük→yüksek risk):
# 1. UNet (denoising) — INT8 genellikle sorunsuz, INT4 kaliteye dokunabilir
# 2. Text Encoder (CLIP) — INT8 genellikle iyi
# 3. VAE Decoder — HASSAS! INT8'de renk kayması yaygın; FP16 tutun mümkünse
#
# Pratik öneri (SDXL):
#   - UNet: INT8 veya FP8 (TensorRT/Mixed precision)
#   - VAE: FP16 veya FP32 (decode hassas)

TensorRT ile Hızlandırma

# NVIDIA TensorRT: modeli özel GPU kernel optimizasyonlarıyla derler
# pip install torch-tensorrt

import torch
import torch_tensorrt

model = torch.hub.load("facebookresearch/dinov2", "dinov2_vits14")
input_example = torch.randn(1, 3, 224, 224).cuda()

# torch.compile gibi ama daha agresif optimizasyonlar
compiled = torch_tensorrt.compile(model, inputs=[input_example])
# SD'de %50-100 hız artışı tipiktir

ONNX: Tek Format Her Yerde

# ONNX: PyTorch/TensorFlow modelini ortak formata çevir,
# her platformda (CPU, GPU, mobil) çalıştır

import torch

torch.onnx.export(
    model,
    input_example,
    "model.onnx",
    opset_version=17,          # Quantization destekli opset
    input_names=["resim"],
    output_names=["tahmin"],
    dynamic_axes={"resim": {0: "batch"}}  # Esnek batch boyutu
)
# onnxruntime ile her platformda çalıştırılabilir
import onnxruntime as ort
oturum = ort.InferenceSession("model.onnx")

İnteraktif: Quantization Kalite-Hız Dengesi

Quantization Trade-off — Hız vs Kalite Eğrisi

Pratik Karar Kılavuzu

  • ✅ Mobil/embedded: INT8 zorunlu (bellek ve pil kısıtı).
  • ✅ Üretim sunucusu: FP16 veya INT8 UNet + FP16 VAE — kaliteyi korur, ~2x hız.
  • ✅ Araştırma/maksimum kalite: FP32/BF16 her şeyde, TensorRT zorunlu değil.
  • ⚠️ SDXL Turbo/Lightning: Zaten hızlı; quantization'ın ek yararı sınırlı olabilir.
