Inference: KV-Cache ve Quantization

📚 L10 · LLM Serisi⏱ ~30 dakika
Bu derste öğrenecekleriniz: Model üretiminin asıl maliyeti nedir, KV-cache nasıl çalışır, prefill ve decode aşamaları arasındaki fark, ve FP16/INT8/INT4 hassasiyetleri. Modeli hızlı ve verimli çalıştırmak.

Inference'ın Gizli Maliyeti

Metin üretimi (autoregressive) token-token çalışır: her yeni token için modelin tüm katmanları çalışır. 1000 token üretmek = 1000 kez full forward pass. Ham haliyle bu kabul edilemez yavaşlıktır. İki kritik optimizasyon bunu çözer: KV-cache ve quantization.

KV-Cache: Tekrar Etme, Sakla

Self-attention'da her token için K (Key) ve V (Value) vektörleri hesaplanır. Token 10'u hesaplarken, token 1-9'un K ve V'leri asla değişmez — çünkü causal masking sayesinde geçmiş, geleceğe bağlı değildir. KV-cache bunları saklar, tekrar hesaplamaz. 

# KV-cache olmadan (yavaş):
for t in range(1000):
    logits = model(tum_metin)       # Tüm metni baştan işle! O(T²) maliyet

# KV-cache ile (hızlı): sadece yeni token işlenir, geçmiş önbellekten okunur
past_key_values = None
for t in range(1000):
    logits, past_key_values = model(yeni_token, past_key_values=past_key_values, use_cache=True)
    # past_key_values: her katman için (1, n_head, t, head_dim) boyutunda
    # Bellek maliyeti: 7B model, 4K bağlamda ~1-2 GB (FP16'da)
💡 Analoji

KV-cache'siz model, bir romanı her yeni cümle için en baştan okuyan yazara benzer. KV-cache ise not alır: "önceki 500 kelime şunlardı" — sadece yeni cümleyi düşünür. Üretim hızını 10-50x artırır, maliyet bellek kullanımıdır.

Prefill vs Decode: İki Farklı Aşama

Prefill
Prompt işlenir (tüm tokenlar paralel)
GPU hesaplama yoğun
KV-cache doldurulur
→
Decode
Her adımda 1 token üretilir
Bellek bant genişliği sınırlı
KV-cache okunur ve genişler
  • Prefill hızı = TTFT (Time to First Token): Kullanıcı ilk kelimeyi ne kadar hızlı görür?
  • Decode hızı = token/saniye: Metin ne kadar akıcı akar? Bellek bant genişliği (model boyutu / bellek hızı) belirler.

Quantization: Daha Az Bit, Daha Az Bellek

# Bellek = parametre sayısı × bit/parametre / 8 (byte)
# 7B model için:
# FP16: 7e9 × 16 bit = 14 GB
# INT8: 7e9 × 8 bit  = 7 GB
# INT4: 7e9 × 4 bit  = 3.5 GB   ← Telefonda bile çalışabilir!

# GGUF (LLM.cpp) quantization formatları:
# Q4_K_M: 4-bit, karma (mixed) strateji, en iyi kalite/hız dengesi
# Q5_K_M: 5-bit, biraz daha iyi kalite
# Q8_0:   8-bit, neredeyse kayıpsız ama en büyük dosya

from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")
model = AutoModelForCausalLM.from_pretrained("meta-llama/Meta-Llama-3-8B", quantization_config=bnb)
# Bellek: ~5 GB (14 GB yerine)

İnteraktif: KV-Cache Büyümesi

KV-Cache Mekanizması — Token Üretimi Sırasında Bellek Büyümesi

Hız — Bellek — Doğruluk Üçgeni

  • Hız: Düşük bit = hızlı (bellek bant genişliği sınırını aşmak için). Decode hızı ≈ bellek_bant_genişliği / model_boyutu.
  • Bellek: INT4 = FP16'nın 1/4'ü. 70B model FP16'da 140 GB, Q4_K_M'de ~40 GB.
  • Doğruluk: Q4_K_M ≈ FP16'nın %97-99'u; INT8 %99+. Ama Q2 (2-bit) önemli kalite kaybı yaşatır.
  • Altın kural: 7B ve üstü için Q4_K_M en iyi denge. Kritik uygulamalar için Q8. Deneysel için Q5.

VLLM ve Ollama: Üretim Altyapısı

# vLLM: yüksek verimli LLM servisi (PagedAttention ile)
# pip install vllm
from vllm import LLM, SamplingParams

llm = LLM(model="meta-llama/Meta-Llama-3-8B-Instruct")
sampling = SamplingParams(temperature=0.7, top_p=0.9, max_tokens=512)
ciktilar = llm.generate(["Bursa'da yapay zeka topluluğu hakkında yaz: "], sampling)
print(ciktilar[0].outputs[0].text)
